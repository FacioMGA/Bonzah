## Intern workflow in the current application

1. Open the verified **Facio Platform** entry URL and choose **Sign in with Facio**. Complete the organization's identity flow. Hosted mode does not ask the intern to paste a development token.
2. Select a customer workspace from the authorized account list, then choose **Open Studio** for its tenant, or create a sandbox if the account role permits it. Studio retains the explicit selected tenant; the account/workspace/tenant identities are not interchangeable. The deployed region is fixed. Keep the returned provisioning operation reference if setup fails; use **Retry provisioning**, which retains the tenant identity.
3. In **Sandbox setup**, attach the reviewed typed requirements JSON. Attachment records a package version; it does not verify the original documents or certify a customer journey. Inspect the retained package and source claims before continuing.
4. Use the existing configuration editor to define the entity, product and its dependencies. Validate it and resolve the relevant gaps. Add the supported manual runtime policy in Sandbox setup, including explicit currency, participant limit, commission and prerequisite settings. Structured rich product authoring is covered by the [training quickstart](../guides/insurance-studio-quickstart.md). Unsupported payment, approval or provider capabilities still block activation. The deployed increment supports explicit independent human review; actual independent-user acceptance remains separate.
5. Review the exact activation candidate, then activate it. If another editor changes a draft, refresh and review the new versions before retrying. A saved draft has no runtime effect until activation.
6. Open **Insurance workspace** from the active release. Create a manual external quote using synthetic inputs, inspect exact premium/capacity/commission values, then use the authorized bind or servicing command. Check the record's release reference when explaining an outcome; an older record can retain an earlier release.
7. For a configuration rollback, supply a known retained release ID and review the current active release. Rollback changes the release used for new quotes; it preserves existing transactions and current drafts. There is no test-data reset operation in this build.
8. Use **MCP connections** to inspect or disconnect your own grants. Actual ChatGPT connection and configuration instructions must be verified for the deployed workspace before this workflow is handed to interns as complete.

Builders may create tenants and operate owned or explicitly assigned targets. Owners and administrators may access account tenants. Viewers may inspect explicitly assigned tenants and cannot mutate configuration or provision tenants. The server rechecks access for every operation; a URL or copied tenant ID does not confer permission. During an in-flight scoped request, target switching is temporarily unavailable; wait for its result before changing tenant.
