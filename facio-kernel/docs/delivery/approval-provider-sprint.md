## Canonical approval contract

Use the existing tenant-scoped business store, canonical operation descriptors, permissions, audit, optimistic concurrency and durable idempotency. UI/API/MCP reads derive from the same retained records. Browser forms collect intentions and evidence; all decisions, applicability, expiry, independence and bind checks remain server-owned. Approval mutations are operator HTTP commands and are not exposed as MCP tools.

| Responsibility     | Required behavior                                                                                                                                                                                                                                                                             |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Request            | Quote-role operator identifies the exact record/version/hash; records reason, evidence and requested expiry. Expiry cannot exceed the quote expiry or seven days from request. The request retains the original creator and requester identities derived by the server.                       |
| Review             | Reviewer inspects the pinned submission, cover selections, price, rule findings, source references and version. A source reference is a declared assertion, not authenticated customer evidence.                                                                                              |
| Approve / decline  | Requires the separate `insurance:approve` permission assigned to account administrators by server policy. The requester and original record creator cannot approve or decline their own case. Record exact request version/hash, outcome, rationale, evidence, actor and time.                |
| Revoke             | Authorized administrator explicitly withdraws the retained approval with reason/evidence and concurrency protection. Revocation must be visible without rewriting historic decisions. It does not cancel an already-bound policy.                                                             |
| Expiry / staleness | Preserve immutable recorded states; project current `expired` or `stale` applicability separately. A later quote/input version cannot silently inherit earlier approval. A newer active product release does not reinterpret an unchanged historically pinned quote.                          |
| Bind               | Optional selected approval reference must resolve in the same authorized tenant and apply to the exact retained quote. Recheck current permissions, record/version/hash, expiry, human decision and every independent gate atomically. Record the consumed evidence with the binding version. |

The recorded states are `requested`, `approved`, `declined` and `revoked`; `expired`, `stale` and `consumed` describe current applicability without editing prior events. Consumed means the bound record retains this review as evidence, not that it can authorize another change. [Published TypeScript schemas](../../src/contracts/approval.ts) govern exact API fields. Rationale, evidence and expiry remain separate typed values rather than a single status dropdown or editable “verified” flag.

The supported approval may satisfy a configured referral or explicit independent-review prerequisite. **It must not override invalid inputs, an inapplicable term/territory, failed rating, declined eligibility, exceeded numeric authority, prohibited backdating, payment or provider requirements.** Required unsupported gates stay blocked. Customer-specific delegated authority, carrier appointments, escalation thresholds, subjectivities and multi-party signing require their actual approved contracts.

## Insurance workspace behavior

The selected record contains a Human review section beside its decision evidence. Show a short risk description, term, premium, selected covers/limits/deductibles and referral reasons before technical references. Exact input, definition, release, record and approval hashes are expandable. Keep durable recorded outcome, effective current status and policy lifecycle visibly distinct.

The quote-role operator can request review with a rationale, supporting references and UTC expiry. An independent administrator can approve or decline a pending applicable request. Self-review controls are disabled with an explanation; server rejection remains authoritative if permissions or state change. Revocation is a separate explicit action. Loading, no request, denied access, stale state, expired request, save error and uncertain request outcomes must be actionable without replacing entered values or another tenant's screen.

The shared application controller owns API calls, CSRF, tenant target, request generation and idempotency. The new presentation module uses only the supplied record, authoritative approval report, current actor/permissions and form state. It does not compute approval eligibility, silently choose a request for binding, or declare remaining gates cleared. A stale response cannot overwrite a newly selected tenant or record. Keyboard operation and a 390px layout must preserve labels, visible focus, status text and accessible error messages.

## Provider boundary in the same sprint

K04 now includes durable scoped requests, atomic worker claims, immutable attempt/receipt history, bounded retries and explicit reconciliation after an ambiguous outcome. Registered live adapters authenticate exact callback bytes with HMAC-SHA256, freshness and nonce controls before mapping. Pinned quote, risk, currency and release provenance are checked. Historical replies remain retained without advancing a newer request's active sequence. Twenty execution/HTTP tests and fourteen existing pure provider tests pass. The actual HTTPS provider UI queues a retained quote, observes worker completion and reloads its receipt without changing insurance price, version or history. Hosted startup registers only the explicitly synthetic training adapter; no customer insurer endpoint, payment processor or screening service is connected.

Inbound acceptance needs the authenticated source, immutable payload/contract version and digest, tenant/record/quote association, replay and ordering outcome, and explicit distinction between observation and verified decision. Outbound execution needs atomic claims, attempt history, bounded retries, failure/recovery state and reconciliation. Pending intent must remain pending until there is an actual acknowledged result. Human approval cannot make an unverified provider response trusted or a queued callback delivered.
