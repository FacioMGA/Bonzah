## Working rules

1. Pull the earliest ready dependency and implement a small complete path through canonical commands, durable state and the existing UI when applicable. Put customer behavior in typed packages or registered adapters.
2. Keep financial amounts as validated decimal minor-unit strings at boundaries and exact integers during calculation. Preserve stored quote, policy, financial and configuration versions. A computed commission is not a receivable, cash movement or payment.
3. Record denied, retry, stale-state and failure outcomes as well as happy paths. A pending outbox row proves durable intent; it does not prove dispatch or reconciliation.
4. Run the applicable checks, inspect the real workflow, pin the build/configuration and attach evidence to the issue. CI guards contracts, scopes and executable behavior. It does not approve a customer rule or certify deployment.
5. Merge verified work to `main`; close an implementation issue only for its stated bounded exit. Customer milestone issues require their complete acceptance matrices, provider boundary decisions and recorded reviewer results.
6. At each checkpoint, update completed work, remaining requirements, failing cases, input dependencies and forecast. Do not declare a milestone green from test counts or a prepared screen. No scheduled automation is established by this document.
