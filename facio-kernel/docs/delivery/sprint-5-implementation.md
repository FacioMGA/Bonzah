## Rust core promoted into Sprint 5 — K16

Uriel explicitly required moving core backend work to Rust during Sprint 5. K16 is now **in progress, targeted September 9**, replacing its earlier after-readiness placement. The canonical premium allocation and commission function executes dependency-free Rust through Node's in-process WebAssembly interface for all supported inputs. This is an executable backend integration, not only a benchmark. The `exact-money-v1` contract and hashes remain unchanged; TypeScript is retained as a conformance oracle and excluded from the hosted runtime image.

Pinned compilation, zero host imports, fixed memory, artifact/ABI verification, a startup probe and `/health.moneyEngine` identify the required engine. Missing or invalid artifacts stop startup before storage initialization; there is no silent TypeScript fallback. [Rust implementation and evidence](../../rust/README.md) records 12,000 deterministic parity cases, additional canonical integration/fixed vectors, native tests and a clean local Linux arm64 container check. Benchmark receipts include full allocator validation/sorting/bridge/result construction and both retained and optimized TypeScript controls. Repeated measurements vary; they do not prove universal optimized-JavaScript CPU gains, whole-service latency, target-host performance or cloud-bill reduction. Further core migrations need their own exact contracts and measurements. Customer production repositories are unchanged.
