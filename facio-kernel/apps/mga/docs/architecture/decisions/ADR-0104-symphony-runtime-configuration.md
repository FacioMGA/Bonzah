# ADR-0104: Symphony configuration in the shared MGA runtime

Status: implemented locally; customer acceptance and deployment are separate.

The source is Cooper/Symphony commit `74499802ee76869c923c2227a18883d06eeb7b4b`. Exact source file hashes are recorded in `backend/modules/insuranceConfiguration/domain/sourceProvenance.json`. Existing dirty source files were preserved; committed source was used. No source database, policyholder records, tenant IDs or customer prices were imported.

Process Builder and product insurance settings are authored once in `ProgramDefinitionVersion.workflow.insuranceConfiguration`. The existing questionnaire and channel components are generated from that source and checked at publication. Changes append a draft. BO, HTTP and Config MCP share the same read/save/publish application services. Publication validates the exact reviewed hash and selected active binder authorities, then commits definition status, mappings and audit in one tenant-scoped PostgreSQL transaction. MCP publication is restricted to active synthetic tenants under a sandbox organization.

Existing products retain their native engines. A registered COMMERCIAL adapter consumes the source commercial coverage calculations, bands, factors, premium dependencies, product-line rates and profession calculations. Its schedule uses the retained transaction definition, selections, quoted price and wording. Configuration cannot install code or assert external underwriting/payment authority. Arbitrary expressions are not evaluated. Unsupported source behavior is reported before publication rather than silently accepted as runtime behavior.

## Source-engine composition boundary

The source calculator exceeds the file-size limit and is split at existing function boundaries under `backend/products/commercial/pricing`. Exactly `premium.ts` and `productLines.ts` are added to the leaf-calculator guard's allowed files: they contain the internal helper caller and helper declaration. The registered COMMERCIAL runtime is the public entrypoint. This is an internal same-engine composition allowance, not a shared transport bypass; no general directory or symbol exemption was added.

The import preserves the source numeric algorithm and audit stages. It does not claim Rust acceleration or exact-integer money parity. The adapter bounds amounts, requires an explicit supported currency, excludes hidden unanswered questions from pricing, and rejects missing FX rates instead of silently keeping the unconverted amount. Published source rules remain tenant values; synthetic training constants are explicitly separate fixtures.

## Executable limits and retained evidence

The current commercial route is enabled only for a server-resolved active synthetic Cyprus tenant with an organization. Its availability profile supplies no live tax, claims or insurance authority. The selected start and end dates are retained; terms longer than one year are rejected because no multi-year rating rule is registered.

Review found source fields that the original calculator accepted but did not consume. Publication therefore rejects product-line source/target routing, non-multiplicative loading instructions and aggregate-minimum semantics. Cross-currency product-line minima fail at evaluation without an explicit conversion. Ready product lines execute; Draft lines do not. Authored risk-code minimums contribute to the floor, and nonempty turnover/limit/deductible tables must contain a matching factor. Invalid loading factors fail instead of being silently skipped. These changes are recorded as adaptations, not identical source behavior.

Question types without a registered renderer/validator, document-required answers, policy-component mapping, output conversion and default-answer behavior remain publication blockers. Native Home/Travel/Health/Motor prices continue to use their existing product engines; source commercial pricing is never mapped onto those engines implicitly.

Every successful canonical rating retains its exact selected programme definition with the quote. Bind readiness rejects an unbound priced record lacking that retained document authority. Existing issued records without a retained definition cannot be reconstructed from a later active mapping. The programme binder picker runs through the same tenant transaction context as the programme and binder rows. Configured agent identities cannot use either canonical bind command, even when generic readiness is clear.

Source compiler 3 explicitly materializes engine questionnaire contract version 1 into a new draft during authoring. Required contact, period, segment and coverage inputs remain available; matching source questions supply reviewed labels/help/settings without duplicate keys. Required engine fields cannot be weakened or changed to incompatible input types. The reviewed immutable definition contains the complete generated sections, and publication verifies them. Compiler 1/2 historical definitions remain unchanged and do not gain fields during reads; an explicit new save and publication is required. This is configuration generation during authoring, not a runtime manifest fallback.

Native programme routes use the canonical `programs.edit` and `programs.publish` permissions. Binder writes use `binders.create`, `binders.edit` and the distinct `binders.publish` key. ADMIN receives these registered permissions; a selected UNDERWRITER membership remains read-only for configuration, regardless of global assignments. The organization BUILDER role alone does not grant operating-tenant authority.

Compiler 4 applies Symphony group scope inheritance on a new save: explicit coverage, binder, segment and section values override nested values, including `All`; omitted group fields preserve question values. Commercial coverage and section selectors resolve against authored coverage rows; segment selectors use stable authored segment IDs. Other product engines must register their selectors before scoped questions can publish. Binder IDs or unique agreement references resolve through active tenant programme links into a retained authority catalogue; publication checks it against current tenant rows. Runtime uses the retained catalogue and server-selected authority, never answer-supplied identity. Scope selectors combine with conditional ancestors for questionnaire visibility, requiredness and effective pricing answers. Empty source filters remain visible as in Symphony; mandatory engine inputs cannot be hidden. Compiler 1–3 definitions are neither rewritten nor given new selectors during reads. An explicit new draft and publication activates compiler 4; an older image must reject it rather than reinterpret it.

Question IDs and slugs share one pricing-answer namespace. Cross-question aliases fail authoring, publication and retained evaluation rather than allowing a visible answer to activate a hidden loading. Commercial segment options have one canonical owner shared by the adapter, scope compiler and UI: configured professions followed by Ready product-line trigger IDs, deduplicated by exact ID. Draft lines do not advertise an executable route. Compiler 4 retains Instruction and informational-only question bodies as read-only paragraph text, subject to the same visibility rules but excluded from requiredness and effective rating answers. Older compiler output is preserved; applying these presentation semantics requires a new reviewed publication.
